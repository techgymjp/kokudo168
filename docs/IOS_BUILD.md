# iOS 版をビルドして App Store に出す手順（Mac での作業）

「酷道168号の星」の iOS 版は、Android 版と同じ Capacitor で作っています（`ios/` フォルダ）。
コードの準備はできているので、Mac では「ビルドして App Store Connect にアップロードする」作業だけを行います。
構成は JET STRIKE（techgymjp/jet-fighter）と同じです。

- Bundle ID：`jp.techgym.kokudo168`（Android のパッケージ名と同じ）
- アプリ名：日本語の端末では「酷道168号の星」、それ以外では「Kokudo 168 Star」
- チーム：Team ID `GNM3VTX9YG`（Xcode の設定に入れてあります）。Apple Developer には**個人で登録**しています（App Store の販売元は個人名になります）
- 対応端末：iPhone（横画面固定）。iPad では iPhone 用の画面で動きます
- 広告：AdMob（iOS 用のアプリと広告ユニット）。起動時に「トラッキングの許可」の確認画面が出ます
  - バナー：タイトル・一時停止・結果画面の下
  - インタースティシャル：「もう一度走る」「タイトルへ」「再開する」（一時停止から）を押したとき
  - リワード：時間切れのとき、1 ゲーム 1 回だけ「広告を見て、その場所から +20 秒で再開」

---

## 0. ブラウザで先にやること（最初の1回だけ）

1. **Apple Developer**（developer.apple.com）→「Certificates, Identifiers & Profiles」→「Identifiers」→「＋」→「App IDs」→「App」
   - Description：`Kokudo 168 Star`（英数字で）
   - Bundle ID：「Explicit」で `jp.techgym.kokudo168`
   - Capabilities：何もチェックしない
2. **App Store Connect**（appstoreconnect.apple.com）→「アプリ」→「＋」→「新規 App」
   - プラットフォーム：iOS ／ 名前：`酷道168号の星` ／ プライマリ言語：日本語
   - バンドル ID：1 で登録した `jp.techgym.kokudo168` ／ SKU：`kokudo168`（あとから変更不可）／ ユーザアクセス：アクセス制限なし
3. **AdMob**
   - 「アプリを追加」→ **iOS** →「ストアに掲載されていない」で登録する（Android 版とは別のアプリ）
   - 広告ユニットを 3 つ作る：**バナー**、**インタースティシャル**、**リワード**
   - アプリ ID（`ca-app-pub-…~…`）と広告ユニット ID 3 つを Claude Code に渡す（`ios/App/App/Info.plist` と `js/ads.js` に入れてもらう）
   - 「プライバシーとメッセージ」→「欧州の規制」のメッセージに iOS アプリも追加する

ID を入れるまでは、Info.plist には Google のテスト用アプリ ID が入っています。本番の広告ユニット ID が空のあいだは、App Store 用のビルドでも広告は出ません。

## 1. Mac の準備（最初の1回だけ）

1. **Xcode** を App Store からインストールする（数十 GB あるので時間がかかります）。インストール後に一度起動し、追加コンポーネントのインストールを済ませる
2. Xcode の「Settings…」→「Accounts」→「＋」で、Apple Developer に登録している Apple ID でサインインする（チームが個人名で表示されれば OK）
3. **Node.js**（LTS 版）を https://nodejs.org/ からインストールする
4. ターミナルでリポジトリを取得する
   ```bash
   cd ~/Desktop   # 置きたい場所（どこでもよい）
   git clone https://github.com/techgymjp/kokudo168.git
   cd kokudo168
   git checkout claude/festive-newton-kj9ayv   # main に統合済みなら不要
   npm ci
   ```
   `git` がないと言われたら、表示に従って「コマンドライン・デベロッパツール」をインストールしてから、もう一度実行します。

2回目以降は、`cd kokudo168` のあと `git pull` と `npm ci` で最新にします。

## 2. 自分の iPhone で動作確認する（テスト広告）

```bash
npm run ios:sync    # ゲームのファイルを iOS のプロジェクトにコピー（テスト広告）
npm run ios:open    # Xcode で開く
```

1. iPhone を USB ケーブルで Mac につなぎ、iPhone で「このコンピュータを信頼」を許可する
2. iPhone の「設定」→「プライバシーとセキュリティ」→「デベロッパモード」をオンにする（再起動を求められます。項目がない場合は、Xcode で一度 iPhone を選ぶと表示されます）
3. Xcode の上部で、実行先に自分の iPhone を選ぶ
4. 左の「App」→「Signing & Capabilities」で、「Automatically manage signing」がオン、Team に自分（個人名）のチームが選ばれていることを確認する
5. ▶（Run）を押すと、iPhone にアプリが入って起動する

確認すること：

- 横画面で全画面表示になる（切り欠き・Dynamic Island に HUD やボタンが隠れない）
- 起動時にトラッキングの確認画面が出る（日本語の端末なら日本語の説明）
- タイトル・一時停止・結果画面の下に**テスト広告**のバナーが出て、プレイ中は消える
- 「もう一度走る」「タイトルへ」「再開する」で**テスト広告**の全画面広告が出る
- 時間切れで「広告を見て続行」が出て、見終わるとその場所から +20 秒で再開できる
- 音が鳴る（iPhone の消音スイッチがオンだと鳴りません）、シェアができる、日本語と English を切り替えられる

## 3. 審査用の録画を用意する（実機・提出前に）

新しいアカウントの最初の審査では、**実機（最新の iOS）でアプリを操作した画面録画**を求められることが多いです（Guideline 2.1 - Information Needed）。先に用意して、提出時に「App Review に関する情報」のメモと一緒に出すと、やり取りが 1 往復減ります。

1. iPhone の「設定」→「コントロールセンター」に「画面収録」を追加する
2. 4 章で TestFlight から入れたアプリ（または 2 章で Xcode から入れたアプリ）を使い、画面収録を開始する
3. 次の順に操作する（2〜3 分）
   - ホーム画面からアプリを**起動**する（起動の瞬間から録る）
   - トラッキングの確認画面に答える
   - 「遊び方」を開いて閉じる、「English」に切り替えて戻す
   - 「走り出す」→ 数十秒走る（追い抜き、対向車をかわす、一時停止 → 再開）
   - 時間切れ → 「広告を見て続行」またはあきらめる → 結果画面 → 「シェアする」
4. 録画は「写真」に保存される。大きいとアップロードに失敗するので、Mac の Finder で右クリック →「選択したビデオファイルをエンコード」→ 720p にするか、Google ドライブの共有リンクを使う

**App Review への説明文（下書き）**：「App Review に関する情報」→「メモ」に貼り、審査から質問が来たら同じ文で返信します。

```
1. Screen recording: (attach the video or paste the Google Drive link here)
2. Purpose and audience: A casual motorcycle racing game for general players aged 13+. The player rides 180 km of Japan's National Route 168 from Hirakata to Shingu, passing slow cars and dodging oncoming traffic and falling rocks.
3. How to use: No login or account is required. Tap "RIDE!" (走り出す) on the title screen. Steer with the left buttons, use GAS and BRAKE on the right. The language can be switched between Japanese and English on the title screen.
4. External services: Google AdMob (banner, interstitial and rewarded ads) with Google's UMP consent form and App Tracking Transparency. No other services; the game runs offline.
5. Regional differences: None, except that the ad consent form is shown only in regions that require it (e.g. the EU/UK).
6. Regulated industries / third-party content: None. All graphics and sounds are original and generated by the app. Real place names and landmarks along the road appear as scenery only.
```

## 4. App Store 用にビルドしてアップロードする（本番広告）

```bash
git pull && npm ci
npm run ios:release   # 本番の広告 ID でコピーする（ここが ios:sync と違う）
npm run ios:open
```

1. Xcode の左で「App」→「General」→「Identity」を開き、**Build の番号を前回より大きくする**（初回は 1。アップロードのたびに 2、3…と上げる。同じ番号は二度アップロードできない）。Version は `1.0.0`
2. 上部の実行先を「**Any iOS Device (arm64)**」にする
3. メニューの「Product」→「**Archive**」（メニューバーが見えないときは、マウスを画面の上端に動かす）
4. 終わると Organizer が開くので、「**Distribute App**」→「**App Store Connect**」→「Upload」で進める（途中の確認は既定のまま「Next」でよい。「Xcode Cloud can automate…」は「Remind Me Later」で閉じる）
5. 10〜30 分ほどで、App Store Connect の「TestFlight」タブにビルドが表示される

輸出コンプライアンス（暗号化）の質問は、Info.plist で「独自の暗号化は使っていない」と設定済みなので、聞かれません。

**注意**：`ios:release` でビルドしたアプリは本番の広告が出ます。TestFlight で確認するときも、**本番の広告はタップしない**でください（AdMob のアカウント停止の対象）。Xcode から iPhone に直接入れて試すときは、`npm run ios:sync` でテスト広告に戻してから実行します。

### TestFlight で確認する

1. App Store Connect の「TestFlight」→「内部テスト」でグループを作り、自分を追加する
2. iPhone に「TestFlight」アプリを App Store から入れ、届いた招待から「酷道168号の星」をインストールする

**App のプライバシー（AdMob を使うアプリの目安）**
Google の「Apple の App Store のデータ開示要件への準備」（AdMob のヘルプ）に、AdMob が収集するデータの一覧があります。必ずそちらを見て最終確認してください。目安は次のとおりです。

- 収集する：ID（デバイス ID）、使用状況データ（広告データ、製品の操作）、診断（クラッシュデータ、パフォーマンスデータ、その他の診断データ）、位置情報（おおよその場所）
- 目的：サードパーティ広告、アナリティクス
- ユーザーに関連付け：しない
- トラッキングに使用：デバイス ID と広告データは「する」

## 7. 自動化の準備（2回目以降を GitHub Actions に任せる場合）

JET STRIKE の `docs/IOS_BUILD.md` 7 章と同じです。API キー（.p8）と配布用の証明書（.p12）は JET STRIKE で作ったものを使い回せます。
techgymjp は組織ではなく個人のアカウントなので、**このリポジトリにも同じ 5 つの Secrets を登録**します。

登録画面：https://github.com/techgymjp/kokudo168/settings/secrets/actions

| 名前 | 内容 |
| --- | --- |
| `IOS_DIST_CERT_P12_BASE64` | 証明書（.p12）を変換した文字列（`base64 -i 証明書.p12 \| tr -d '\n' \| pbcopy`） |
| `IOS_DIST_CERT_PASSWORD` | .p12 を書き出したときのパスワード |
| `ASC_KEY_ID` | API キーのキー ID |
| `ASC_ISSUER_ID` | Issuer ID |
| `ASC_KEY_P8_BASE64` | API キー（.p8）を変換した文字列（`base64 -i AuthKey_XXXXXXXXXX.p8 \| tr -d '\n' \| pbcopy`） |

登録が終わったら、Claude Code に「iOS の自動アップロードのワークフローを作って」と頼みます。

**注意**：証明書（.p12）、そのパスワード、API キー（.p8）は、チャット・AI へのアップロード・リポジトリへのコミットで**絶対に共有しない**でください。

いまある `.github/workflows/ios.yml` は、push のたびに GitHub の Mac で「署名なしでビルドできるか」だけを確認するものです（App Store には上げません）。

## つまずきやすいところ

| 症状 | 対処 |
| --- | --- |
| アップロードで「同じビルド番号がすでにある」 | General の Build の番号を上げてから Archive し直す |
| アップロードしたビルドが選べない | App Store Connect のバージョンを `1.0.0` に直して保存する |
| Signing でエラー（チームが選べない、証明書がない） | Xcode の Accounts で Apple ID にサインインし直し、Team に自分のチームを選ぶ。「Automatically manage signing」をオンにする |
| 実行先に iPhone が出ない | ケーブルをつなぎ直し、iPhone で「信頼」を許可。デベロッパモードをオンにする |
| 実行先に「iOS 26.x Not Installed」 | 「Get」で iOS の部品をダウンロードする（8 GB ほど。Archive にも必要） |
| ビルドが古いゲームのまま | `npm run ios:sync`（または `ios:release`）を実行し忘れている。`git pull` してから実行し直す |
| 6.9 インチのスクリーンショットが入らない | 欄は「中型ディスプレイ」。`docs/store/ios/6.3inch/`（2622 × 1206）を使う |
| 「審査用に追加できません」 | 「コンテンツの配信権」と「App のプライバシー」のプライバシーポリシー URL を入力して保存する |
| 本番広告とテスト広告の取り違え | App Store 用は必ず `npm run ios:release`。実機で試すときは `npm run ios:sync` に戻す |
| 審査で「Xcode が古い」と言われる | Xcode を最新版に更新してから Archive し直す |
